## 이번 세션에서 발견한 환경 상태 — 이전 기록과 달랐던 점

이전 인수인계 문서는 "pgvector 계속 켜둔 상태", "Homebrew postgresql@17 중지해둔 상태"라고
적었지만 실제로는 **둘 다 사실과 달랐다**:

- Homebrew `postgresql@17`이 여전히 5432를 점유하며 실행 중이었다(`brew services stop`이
  이 환경의 Homebrew 버그로 먹지 않는 상태였던 것으로 보인다) → `launchctl unload -w
  /opt/homebrew/opt/postgresql@17/homebrew.mxcl.postgresql@17.plist`로 해소.
  데이터는 건드리지 않았다. 복구하려면 `launchctl load -w` 동일 경로.
- Docker 데몬이 꺼져 있었고 pgvector 컨테이너·볼륨 자체가 없었다(이전 검증 시도가 남긴
  흔적이 없다는 뜻) → `open -a Docker` 후 `docker compose up -d`로 새로 기동.

박성우도 같은 5432 충돌을 독립적으로 겪었는데, `docker-compose.yml`을
`${HELPDESK_POSTGRES_PORT:-5432}:5432`로 바꿔 로컬 서비스를 안 건드리고 포트만 우회하는
방식을 썼다(본인 브랜치, 아직 main 미반영) — 로컬 서비스를 내리는 것보다 안전한 방식이라
저장소 표준으로 채택을 제안할 만하다(제안 내용은 아래 "PR" 절 참고 — 실제 전달은 PR
본문으로 한다).

5. **조항 구분** — `휴학`·`자퇴`·`제적` 키워드/자연어 질문 모두 서로 다른 정확한 조항으로

6. **threshold 실측 조정** — 아래 별도 절 참고.

## threshold 실측 조정 — 0.5 → 0.3

`api/admin/chunks`의 단어 단위 질의와 실제 채팅 경로(자연어 전체 문장)는 유사도 스코어
스케일이 다르다는 걸 확인했다. 자연어 질문 기준 실측값:

| 질문 유형 | 최고 score |
|---|---|
| 무관 질문("오늘 학생식당 점심 메뉴가 뭐예요?") | 0.287 |
| 자퇴(정확한 조항 매치) | 0.369 |
| 제적(정확한 조항 매치) | 0.434 |
| 휴학·졸업요건(정확한 조항 매치) | 0.52~0.65 |

기존 `threshold: 0.5`는 무관 질문은 잘 걸렀지만 자퇴·제적처럼 근거가 실제로 있는 질문까지
걸러내(재현율 손실) `POST /api/chat`이 "정확한 규정을 확인할 수 없습니다"로 잘못 답했다.
`threshold: 0.3`으로 낮춘 뒤 재검증하니 무관 질문은 여전히 걸러지고(0.287 < 0.3) 자퇴·
제적도 정확한 근거로 답변했다. `chunk-size`(300)·`min-chunk-size-chars`(150)는 preview가
조항 단위를 온전히 담고 있어 조정하지 않았다.

사소한 노이즈 1건: "제적 사유가 뭐가 있나요?" 답변 출처에 `scholarship-policy.md`가
threshold 턱걸이(0.3 근처)로 낀 경우가 있었다. 답변 품질 자체는 문제없었지만, `topK`를
줄이거나 threshold를 조금 더 올리는 미세조정 여지는 남아 있다 — 다음 라운드에서
실제 사용 패턴을 보고 판단.
