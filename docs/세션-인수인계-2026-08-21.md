## 막힌 지점 — OPENAI_API_KEY

실습용으로 제공받은 키를 **서로 다른 3개** 시도했는데 전부 동일하게 거부됐다:

```
401 invalid_api_key: Incorrect API key provided: sk-proj-...
```

- 세 키 모두 길이 164자로 동일, `T3BlbkFJ` 마커도 정상 — **형식은 완전히 정상**이라
  복사 실수 가능성은 낮다.
- `insufficient_quota`(잔액 부족)가 아니라 `invalid_api_key`(키 자체가 없음)라서
  과금/크레딧 문제도 아니다.
- `curl -H "Authorization: Bearer $KEY" https://api.openai.com/v1/models`로 가볍게
  확인 가능(굳이 앱을 안 띄워도 됨).
- **결론: 키 발급/배포 쪽 문제로 보인다.** 강사·운영진에게 "발급받은 키가
  `invalid_api_key`로 거부된다"고 그대로 전달해서 실제 활성 키가 맞는지 확인 요청 필요.

앱이 이 상황에서 죽지 않고 정상 기동하는 것도 확인했다 — `AGENTS.md`의 "AI 인프라 실패가
전체 기동을 막지 않는다" 원칙대로 `IngestService`가 예외를 잡아 로그만 남긴다. 즉 이건
설계대로 동작한 것이지 버그가 아니다.

## 다음 세션에서 할 일 (새 키 확보 시)

1. `export OPENAI_API_KEY="sk-..."`로 세션에 주입 — **`.env` 파일에 쓰지 않는다**
   (이 프로젝트는 API 키를 항상 export로 다루는 게 원칙)
2. 빠른 키 유효성 확인: `curl -s -o /dev/null -w "%{http_code}" https://api.openai.com/v1/models -H "Authorization: Bearer $OPENAI_API_KEY"` → 200 확인 (`bootRun` 전체를 안 띄워도 됨)
3. `docker compose ps`로 pgvector 살아있는지 확인(꺼졌으면 `docker compose up -d`)
4. `./gradlew bootRun`
5. 검증 6단계:
   - `GET /api/admin/chunks?q=졸업요건&topK=5` — source·version·score·preview 확인,
     앵커 md와 신규 PDF가 둘 다 잡히는지
   - `q=교수 명단`, `q=연락처`로 PII 미유입 확인
   - 앱 재시작 후 같은 질의 재검색 — 청크 중복 여부(재색인 delete 동작 확인)
   - `q=휴학`, `q=자퇴`, `q=제적` — 서로 다른 조항이 구분되는지
   - `q=점심 메뉴` 같은 무관 질의로 score 확인 → `helpdesk.rag.threshold: 0.5` 실측 조정
   - `http/samples.http` 시나리오 ①(규정 RAG)·⑦(폴백) 회귀 확인
6. 결과에 따라 `chunk-size`(현재 300)·`min-chunk-size-chars`(현재 150) 조정
7. 문제 없으면 커밋 → 아래 "박성우에게 전달" 내용 공유 → PR

## 환경 메모

- pgvector 컨테이너: 계속 켜둔 상태(`docker compose ps`로 확인). 꺼져 있으면
  `docker compose up -d`.
- 로컬 Homebrew `postgresql@17`이 5432 포트를 선점해 앱이 엉뚱한 DB에 붙는 문제가
  있었다 — `brew services stop postgresql@17`로 중지해둔 상태. 이 실습과 무관하게 쓰던
  서비스라면 검증 끝나고 `brew services start postgresql@17`로 복구할지는 직접 판단.
- `.env` 파일은 없다 — API 키는 항상 `export`로만 다룬다(사용자 원칙, 다음 세션도 유지).
